# Agent 编辑工作流

## 一次采集与取舍

从用户指定的 RSS / Atom 清单收集一次窗口内线索；可用 RSSHub 把支持的网站转为 feed。路由有效性、认证要求和自建实例参照 [RSSHub 官方文档](https://docs.rsshub.app/)，不自动部署服务或导入个人凭据。冻结抓取时刻、窗口和原始响应，未注明日期的条目标记为待核验，不直接认定为当日新闻。

URL 去重只解决重复链接。不同链接描述同一事件，Agent 需要合并新增事实、案例与演示，保留证据来源。筛选依据为实质变化、受众影响、可信度和讨论价值，不编造热度。正文最多 20 条、快讯最多 10 条，是上限，不是目标数量。正文默认不超过 420 秒，放不下就减少事件，不靠加速或掏空解释硬塞。

精简新闻数量，不精简关键内容。发布产品或模型时，把核心能力、具体用途、重要变化、开放地区/套餐和必要限制融入自然叙事；不机械念“它是什么、能做什么、怎么工作、怎么使用”。观点保留归因，预告不写成已经发布，厂商宣称不冒充实测结论。

同一企业连续播报，联合事件只播一次，关联产品映射到所属企业。正文放需要解释的重要事件，快讯放独立一句即可讲清的有效变化，不把淘汰项塞进快讯，不重复正文凑数量。

## 原文与画面

RSS 是线索，不是核验完成。回原始公告、原帖或原报道确认日期、功能、数字与条件。为关键说法保存链接和支持它的摘录，新增事实不能只有截图标题。官方演示、自己的实操录屏、示意动画要明确区分；没有成功实测就不说“我测过”。

截图工具使用独立无登录浏览器。按讲解需要截取可读区域，不把整篇长文缩成无法阅读的小字。逐张实际看图后记录审核，成功且未变化的素材复用；失败项修复用新 ID/目录保留原始记录。演示素材需自行确认使用权限，原文署名与证据保留真实来源。

## 稿件与声音

开场用有依据的反差或悬念抓住注意力，最多预览 3 个重点，不念全篇目录。夸张表达可以，数字、状态和适用条件不能变。正文直接讲已确认的结论，删去反复提醒、空泛点评和故意绕回的问句。中文口播可用逗号、问号、叹号和换行，避免句号；媒体归因可写“据有关媒体报道”，证据仍保留媒体原链接。

每个 cue 是自然短句，尽量控制 12–32 个中文字符，最长 65 字符；长句应按语义拆开，不按均匀时长硬切。每句独立合成，默认句后停顿 350ms，转折/换段可 450–700ms，小分句可 200–300ms。情绪与语义一致，语速始终 1.1，不后期加速。实际听衔接，不能只看字幕时间表。

## 审核与交付

组装后检查各句中点、场景首尾、媒体切换、长字幕和封面，说明看过哪些画面、是否完整听过。`review` 记录操作者实际检查，不自动推断通过。用户只预览就停在 Studio；用户要求导出才渲染。交付前核对当前构建哈希、帧数/编码、音轨相关性和全片解码，不冒充主观完整试听。外部上传、发布与定时任务必须在当前授权范围内。
